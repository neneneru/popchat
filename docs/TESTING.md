必要環境はNode.js 20以上とPython 3です。PythonはZIP生成と再現性検査に使用します。第三者パッケージの追加は不要です。

```sh
npm test
npm run check
```

主な検査対象:

- 対象URL、チャンネル名・動画ID、設定値、AUTO / SIDE / BOTTOM / HIDEの配置計算。
- Twitchの歯車メニューへの限定追加、既存項目・ハンドラーの保持、重複防止、不明・非表示・曖昧な構造で追加しないこと。
- 10言語の認識対象メニューと11言語の拡張表示を組み合わせた検査。カタログの完全性、翻訳キー・プレースホルダー、英語フォールバック、RTL設定。
- ライブの公式チャット表示、再読込、チャットだけの別窓、HIDEでのiframe保持。
- 共通の36pxヘッダー・24pxボタン、配置の選択状態、キーボード操作、狭幅時の配置計算。
- ライブ最前面小窓への同じvideo要素の移動と復元、連打・失敗・動画交換・遅延要求の無効化。
- アーカイブの現在位置付き公式URL、同期的な別窓起動、成功後の元動画の停止、ポップアップ失敗後の再試行。
- アーカイブの公式プレイヤー・ネイティブリプレイの配置、要素交換やページ遷移時の解除、ライブチャットで代用しないこと。
- 同意前のページ未処理、保存失敗、同意取り消し、非同期処理との競合、ページ離脱・BFCache復帰時の監視とタイマーの管理。
- storageのみの権限、対象2ホスト、JavaScript構文、ローカル資産、不要ファイルや禁止APIの検査。
- ZIPの再現性、CRC、manifestの配置、実行用ファイルの完全性。

テストはNode.jsのDOM/API代替実装を使います。実ブラウザのCSS描画、Twitchの再生・リプレイ同期、すべての環境での動作を検証した数ではありません。VODの最前面表示は提供していません。

## 利用環境での確認手順

確認時は拡張のバージョン、ブラウザのバージョン、OS、Twitchの表示言語を記録してください。同じ機能を変更する拡張を複数同時に有効にしないでください。

1. 初回の説明タブ、または拡張アイコンの「使い方・設定」を開きます。同意前と「今はしない」の状態ではTwitchページが変わらないことを確認し、有効化します。
2. ライブの通常配信ページで歯車メニューを開きます。純正の「ポップアウト」は従来どおり動き、隣の「ポップアウト（最前面）」が一つだけ表示されることを確認します。
3. 通常ポップアウトと最前面小窓で、配置、チャット再読込、チャットだけの別窓を確認します。小窓を閉じると映像が元へ戻ることも確認します。
4. リプレイを利用できるアーカイブで「ポップアウト（チャットリプレイ付き）」を開きます。元動画が停止し、別窓に映像と公式リプレイが表示されることを確認します。
5. 配置切り替え、サイズ変更、キーボード操作、別アーカイブへの移動、別窓の終了を確認します。別窓を閉じても元タブは残り、必要に応じてそこで再生を再開できます。
6. 「使い方・設定」で無効化し、追加チャット・ヘッダー・メニュー項目が取り除かれることを確認します。ライブ最前面の映像は元へ戻り、通常の別窓は自動では閉じません。
7. 新規インストール時に説明タブが一つ開き、更新・拡張の再読み込み・ブラウザ起動では自動で増えないことを確認します。

メニューの文言や構造が認識できない場合、追加項目を出さずに止まる設計です。Twitch本来の操作を書き換えたり、別の場所に起動ボタンを出したりしません。
